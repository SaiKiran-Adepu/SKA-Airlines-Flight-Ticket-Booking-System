🆕 Version 41 Update
⚠️ Critical Security Fix at Payment Gateway
Previously, the payment gateway QR code (UPI/Pay QR) was generated on the frontend (HTML/JS).
This allowed anyone to open Inspect Element → Edit QR value → Pay to their own account — breaking payment integrity. 🔓❌

🔒 Fix Implemented:
Now, sessions securely store important payment data like total fare, txn_id, transaction mode on the backend.
The QR code is generated server-side with these session values, so it cannot be tampered with via frontend inspection.

✅ Secure Payment Flow:

When the user reaches the payment page, backend saves total_fare, txn_id, and trm in session/DB.

Frontend requests /generate_payment_qr with no sensitive parameters.

Server builds and returns a secure QR as an image.

Even if a user edits HTML, the QR is always generated from backend session data, not from the frontend input.

⚡ Benefits:

Users cannot modify QR code via Inspect Element.

Payment integrity is fully protected.

Your payment status polling (check_payment_status) continues to work smoothly with secure txn_id.

THE CORRECTED AND ADVANCED allocate_seat_number trigger with no hardcoded seat numbers directly from the db table seat_master

DROP TRIGGER IF EXISTS allocate_seat_number;
DELIMITER $$

CREATE TRIGGER allocate_seat_number
BEFORE INSERT ON airline_sitting
FOR EACH ROW
BEGIN
    -- ✅ Variables
    DECLARE class_type VARCHAR(100);
    DECLARE journey_date VARCHAR(100);
    DECLARE flight_num VARCHAR(11);
    DECLARE candidate_seat VARCHAR(10);

    -- ✅ Get reservation details
    SELECT flight_class, jd, flight_Number
    INTO class_type, journey_date, flight_num
    FROM airline_reservation
    WHERE PNR = NEW.PNR;

    /* =========================================================
       ✅ SINGLE STEP: Pick NEXT AVAILABLE SEAT IN ORDER
       (handles both cancelled + fresh seats automatically)
    ========================================================= */
    SELECT sm.seat_number
    INTO candidate_seat
    FROM seat_master sm
    WHERE sm.class_type = class_type

    -- ❌ exclude already occupied seats
    AND NOT EXISTS (
        SELECT 1
        FROM airline_sitting s
        JOIN airline_reservation r ON s.PNR = r.PNR
        WHERE r.flight_class = class_type
          AND r.jd = journey_date
          AND r.flight_Number = flight_num
          AND s.seat_number = sm.seat_number
          AND s.seat_status IN ('ACTIVE','REUSED')
    )

    -- ❌ avoid duplicates within same PNR
    AND sm.seat_number NOT IN (
        SELECT seat_number
        FROM airline_sitting
        WHERE PNR = NEW.PNR
    )

    ORDER BY sm.row_no, sm.seat_col
    LIMIT 1;

    -- ✅ assign seat
    IF candidate_seat IS NOT NULL THEN
        SET NEW.seat_number = candidate_seat;
        SET NEW.seat_status = 'ACTIVE';
    END IF;

END$$

DELIMITER ;

🔒 Session Management Improvements

Fixed a major issue related to session persistence. Previously, if a user or admin logged into the application on a device and forgot to log out, the session could remain active indefinitely, especially when the application was hosted.

To address this issue:

🛡️ Developed session_manager.py and placed it inside the security folder.
⚙️ Integrated it with airline.py alongside utc_time.py.
⏳ Implemented automatic session expiration based on inactivity.
👨‍💼 Admin Session
If an administrator forgets to log out, the system will automatically terminate the session after 20 minutes of inactivity.
👤 User Session
If a user forgets to log out, the session will automatically expire after 2 hours of inactivity.

This enhancement improves both security and resource management, particularly in hosted environments. 🔐
